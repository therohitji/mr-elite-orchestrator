1. The Core Logic Pipeline (The "Algorithm")
We implement a Waterfall Classification Algorithm. The data flows through layers of increasing intelligence. We
do not jump straight to the most expensive model.
• Layer 1 (The Reflex): Deterministic Heuristics (O(1) execution time).
• Layer 2 (The Brain): Semantic Analysis via LLM (Probabilistic classification).
• Layer 3 (The Judge): Structural Validation (Schema enforcement).
2. Component Breakdown & Implementation Logic
A. Heuristic Filter (The "Reflex")
What it is: A predefined set of Regex patterns and strict string matching rules.
Why: To prevent wasting tokens on inputs that are strictly programmatic or conversational "noise."
Implementation Logic:
• Input Sanitization: Trim whitespace, normalize to lowercase.
• Pattern Matching:
◦ Greeting_Pattern : ["hi", "hello", "hey"] $\rightarrow$ Route directly to Chat Node.
◦ System_Command_Pattern : ["/reset", "/logout", "/status"] $\rightarrow$ Route directly to System Ops Node.
◦ Cancel_Pattern : ["stop", "cancel", "abort"] $\rightarrow$ Route to Interrupt Handler.
• Technical Spec: Use Python’s re module. If a match is found, return immediately (Short-circuit). Do not call
the LLM.
B. Semantic Router (The "Brain")
What it is: A specialized LLM call (using a small, fast model like gpt-4o-mini) tasked only with classification, not
execution.
How it works: It projects the user's vague language into one of our four fixed Intent Buckets1.
The Buckets:
1. CONVERSATIONAL : Non-functional banter.
2. RETRIEVAL_RAG : Asking for existing data (Policy, Status, History).
3. ATOMIC_TASK : A single action with no dependencies (e.g., "Draft email").
4. COMPOSITE_GOAL : A multi-step workflow requiring the Planner (e.g., "Hire SDE").
C. Complexity Score (The "Resource Allocator")
What it is: A scalar value (1-10) determining how much "thinking time" (and cost) we allocate.
Scoring Rubric (The Logic):
• Score 1-3 (Low): Single tool required, no ambiguity. Action: Direct Execution.
• Score 4-7 (Med): Multiple tools, but linear execution (Step 1 $\to$ Step 2). Action: Standard Planning.
•
Score 8-10 (High): High ambiguity, high risk, requires policy checks or human approval2. Action: "Deep Thought"
Planning (Reflection Loops).
Algorithm:
The Semantic Router evaluates complexity based on:
• Ambiguity: "Send it to him" (Who is him?) = High Score.
• Criticality: "Delete database" = High Score (10).
• Temporal Scope: "Monitor for next week" = Medium Score.
D. Reasoning (The "Audit Trail")
What it is: A required text field where the model explains why it chose the classification.
Why: This is vital for the Evaluation Layer3. If the router misclassifies a "Fire Employee" request as a simple

import uuid
import networkx as nx
class AtomizerEngine:
def process_plan(self, cot_plan_json):

atom = Atom(**step) # Pydantic Validation
atom.atom_id = str(uuid.uuid4()) # Hardcoded UUID
atoms.append(atom)
# 2. Dependency Resolution (Mapping Index to UUID)
for atom in atoms:
new_deps = []
for dep_index in atom.dependency_step_indices:
target_uuid = atoms[dep_index].atom_id
new_deps.append(target_uuid)
atom.dependencies = new_deps # Update to UUIDs
# 3. Hardcoded Tagging Logic
for atom in atoms:
if "money" in atom.arguments or "pay" in atom.tool_name:
atom.tags.append("risk_high")
atom.tags.append("policy_check_required")
# 4. Graph Validation (The Algorithm)
if not self._validate_dag(atoms):
raise Exception("Invalid Plan: Cycle Detected")
return atoms
def _validate_dag(self, atoms):
G = nx.DiGraph()
for a in atoms:
G.add_node(a.atom_id)
for dep in a.dependencies:
G.add_edge(dep, a.atom_id)
return nx.is_directed_acyclic_graph(G)
